# 四周输入扩展计划

> 建立日期：2026-09-29 ／ 起算：2026-W40（09-29 起），按自然周（`Asia/Shanghai` 周一 00:00）
> 配套：《01_来源网络V2》《02_检索词库》
> 设计前提：**单人、每周约 1.5 小时**（两段 45 分钟即可），不增加报告篇幅，只扩输入面
> 与既有机制的关系：本计划是规范 §5.2「B 类四周轮换专项」的**执行层细化**，并回填已停摆两期的 §5.5「16 方向覆盖审计」

## 第 1 周｜交互设计指南与用户真实反馈

**本周要回答**：对话该怎么设计？真实家庭里到底哪里坏了？

| 项 | 内容 |
|---|---|
| **固定扫描源** | ① Apple HIG — Siri／机器学习章节 ② Alexa Design Guide ③ Google Conversation Design ④ Google Cloud Dialogflow 语音 Agent 设计最佳做法（指标体系） ⑤ Microsoft HAX Toolkit |
| **专项检索源** | 黑猫投诉（按问题类型：识别／计费／广告／售后／隐私）／Reddit `r/amazonecho` `r/alexa` `r/googlehome`／应用商店评论／知乎·B站·小红书·什么值得买（老人·儿童·方言场景）／厂商官方社区 |
| **检索式** | 见《02_检索词库》§1、§2、§3、§5 共 6 条（最少 3 条） |
| **预计产出** | ① **设计基线卡**：从 5 个指南里各提炼 ≤3 条可操作判据（不写成综述） ② **用户痛点聚类表**：按「问题类型 × 场景 × 出现次数」，目标 ≥20 条原始线索 → ≥5 条候选 ③ 本周扫描日志 |
| **盲区检查** | 方向 9（情绪语气）、方向 10（主动交互与信任）是否出现 ≥1 条候选；若仍为 0，写入下轮任务 |
| **不收录条件** | ① 单条用户评论直接作为体验结论（须 ≥3 条独立来源）② 情绪化表达本身（只留问题类型）③ 无原始凭据的二手转述 ④ 设计指南被当作「用户效果证据」（指南最高只到概念级） |
| **升格判据** | 线索 → 候选：与 16 方向之一相关 **且** 能定位到具体交互环节 **且** 至少一份可回溯来源 |

## 第 2 周｜HCI、语音与多模态研究来源

**本周要回答**：学界已经验证了什么机制？证据强度到哪一档？

| 项 | 内容 |
|---|---|
| **固定扫描源** | ① SIGDIAL／ACL Anthology ② INTERSPEECH／ISCA Archive ③ CHI／UIST／CSCW／ICMI（ACM DL） ④ ICASSP（IEEE Xplore） ⑤ arXiv `cs.HC`＋`eess.AS`（**仅作实验级**） ⑥ ACM Interactions 会议日历（跟踪下一批截稿与召开） |
| **专项检索源** | `site:aclanthology.org`、`site:dl.acm.org`、`site:isca-archive.org`、`dblp.org`、`openreview.net` |
| **检索式** | 见《02_检索词库》§1、§2、§5、§7 共 4 条，其中至少 2 条带 `site:` 限定 |
| **预计产出** | **论文卡**（每篇 5 行内）：问题 / 方法 / 指标 / 样本与条件 / 证据边界 —— 目标 5—8 张。**只做卡片，不做趋势判断** |
| **盲区检查** | 方向 4（原生音频与副语言）、方向 1（实时语音与全双工）；核对是否出现「副语言」「轮次」「失败恢复」「记忆」四类关键词 |
| **不收录条件** | ① arXiv 预印本被当作已同行评审 ② 无样本量／无测试条件的评测结论 ③ 第三方榜单排名被当作产品可用证据 ④ 单次 demo 视频被当作可复现 |
| **时效提醒** | 顶会论文有 3—9 个月时滞（ICASSP 5 月／CHI 4 月／INTERSPEECH 9 月／UIST 11 月）。**检索时先按「最近一届已出论文集」取，不要只搜新闻** |

## 每周固定动作（与运行手册第 3 步对齐）

```
① 记录扫描日志
   日期 / 时间窗 / 执行的检索式 / 命中数 / 不可访问来源 / 失败原因
② 登记原始线索池（符合《01_来源网络V2》§0.1—0.3 标注）
   线索 ← 来源名称 / 入口 / 来源位置 / 证据成熟度 / 一句话事实 / 对应 16 方向
③ 升格候选池（满足升格判据的移出）
④ 更新持续观察池（设计指南、标准、无障碍等基线类来源的变更）
⑤ 写覆盖审计（16 方向命中表）
⑥ 写明本周盲区与不收录清单
```

> **纪律**：输入层产物**不直接进入报告**。汇总与收录仍走运行手册第 4 步起的合同流程；本层只保证「有料可筛」。

## 单人执行的节拍（每周两段，共约 1.5 h）

| 时段 | 动作 | 时长 |
|---|---|---:|
| 第 1 段（周一） | 按本周「固定扫描源」逐层快扫，记扫描日志 | 45 min |

**冷启动提示（第 1 周）**：清单类来源（设计指南、标准、无障碍）首次扫描会明显超时，建议第 1 周只做「入口确认 ＋ 现状快照」，把逐条判据留到第 2 轮。

## 四周结束时的验收自检

| 检查项 | 判据 |
|---|---|
| 设计指南类是否有产出 | 层1 ≥1 张设计基线卡 |
| 用户反馈类是否非零 | 层2 原始线索 ≥20 条（跨 ≥3 个问题类型） |
| 研究类是否非零 | 层3 论文卡 ≥5 张（跨 ≥3 个会议） |
| 候选是否都有来源标注 | 100% 标注位置＋成熟度 |
| C 类是否仍被当唯一依据 | 0 例 |
| 覆盖审计是否恢复 | 连续 4 周有 16 方向命中表 |
| 盲区是否收敛 | 方向 9／10 从「连续未命中」变为「有候选」 |
