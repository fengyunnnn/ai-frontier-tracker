# 问题驱动检索词库（中英双语，可直接复制）

> 建立日期：2026-09-29 ／ 配套：《01_来源网络V2》《03_四周输入扩展计划》
> 目的：把「公司名 + AI + 发布」式的被动检索，换成**由问题驱动**的主动检索

---

## 0. 怎么用这一份

### 0.1 四段式公式

```
交互机制 × 用户/场景 × 证据类型 × 产品或平台
```

四段不必全填，**至少填前三段中的两段**。只填一段＝退回「公司名 + 发布」的旧写法。

| 段 | 可选项（见 §1—§8） |
|---|---|
| 交互机制 | 打断／轮次／沉默／澄清／纠错／失败恢复／主动交互／记忆／副语言／声纹…… |
| 用户/场景 | 老人／儿童／多人／访客／方言／口音／电视声／厨房声／弱网／强噪 |
| 证据类型 | 论文／基准／A-B 测试／模型卡／帮助文档／版本说明／采购公示／投诉聚类／实测 |
| 产品或平台 | 机顶盒／中屏／大屏／遥控器／音箱／App／SDK／芯片平台 |

### 0.2 运算符速查

| 用途 | 写法 | 例 |
|---|---|---|
| 精确短语 | `"…"` | `"turn-taking"` |
| 站内限定 | `site:` | `site:aclanthology.org` |
| 标题限定 | `intitle:` | `intitle:"release notes"` |
| 并列／排除 | `OR` / `-` | `(老人 OR senior) -广告` |
| 文件类型 | `filetype:pdf` | `filetype:pdf model card` |
| 时间窗 | 写明年度 | `2026` |
| 学术同义堆叠 | `A OR B OR C` | `(barge-in OR interruption OR overlap)` |

### 0.3 三条使用纪律

1. **先定问题，再定检索式**。想不清「我要回答哪一个交互问题」时，检索式再漂亮也没用。
2. **同一问题至少换一种来源层重检一次**（学术／官方／用户三选二），否则拿不到交叉证据。
3. **检索式的产物是候选，不是结论**。命中后必须回溯到原始来源再登记。

## 9. 不要这样用（反例）

| 反例 | 问题 | 换成 |
|---|---|---|
| `小米 AI 发布` | 只拿到公关稿，拿不到机制与失败场景 | `小米 语音 中屏 主动 播报 打扰 用户反馈` ＋ `小米 语音 轮次 打断 帮助中心` |
| `全双工 语音 公司` | 抓到的都是融资与发布会 | `"full-duplex" speech interruption recovery evaluation site:aclanthology.org` |
| `语音助手 用户 吐槽` | 全是情绪，无法聚类 | `天猫精灵 识别 不准 投诉`（按问题类型分，不按情绪分） |
| `AI 语音 2026 趋势` | 趋势报告互相抄，无原始来源 | 拆成 §1—§8 的具体机制式 |
| `老人 智能屏` | 拿到带货软文 | `小度 智能屏 老人 长辈模式 关闭 闲聊 实测` |
