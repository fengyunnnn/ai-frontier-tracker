## 三、必须遵守的原则（写在入口，防止随后滑回去）

1. **不靠增加新闻网站解决问题。** 新增的是**层次**（设计指南／用户反馈／顶会／开发者／合规／芯片／平台工程），不是更多的媒体。
2. **聚合站、门户、公众号、媒体只作线索入口**，不得单独构成重点事项的事实依据（规范 §5.3）。
3. **每个来源同时标注两个维度**：
   - 来源位置：**原始 / 二手 / 线索**
   - 证据成熟度：**概念 / 实验 / 开发者可用 / 产品可用 / 规模验证**
4. **arXiv 可作原始研究来源，但不等于同行评审，也不等于产品可用**（上限＝实验）。
5. **单条用户评论只能作线索**，不得直接形成用户体验结论（建议 ≥3 条独立来源交叉才升格）。
6. **设计指南是长期设计基线**，不要求每周出现新闻；它证明「应该怎样」，**不证明「用户用了怎样」**。
7. **厂商自报数据与第三方榜单自报指标只作线索/概念**，不得单独支撑重点结论。
8. **中国监管材料可用于国内合规判断；FTC／COPPA 仅用于国际产品、设计与风险观察，不得推导为中国合规要求。**

**2026-09-29 第三轮新增（证据可用性核验纪律）**：

9. 每个重要候选必须保留**原始 URL、访问日期、具体页面或章节位置**。
10. 所有**精确数字**（时延、成本、模型排名、用户规模、部署省份）**逐条标注来源类型**，取值限定：厂商官方文档｜厂商自报 Benchmark｜GitHub 参数｜第三方评测·估算｜真实商用数据｜监管或法规原文｜同行评审论文。
11. **没有可追溯原始出处的数字，降级为线索，不写入正式条目。**
12. **交互研究类卡片允许没有硬数字**，但只能写成「提供了值得验证的交互机制证据」，**不得**写成「已证明用户体验改善」。
13. **限研究用途的模型可进候选池与战略雷达**，但必须标记「研究用途／不可直接商用／未验证家庭终端可用性」，**不得**进入「已可落地」表述。

**2026-09-29 第四轮新增（事件粒度）**：

14. **进入处理层的单位是「最小事件」，不是「候选包」** —— 会议论文集、合并了多子议题的候选必须**拆成单篇／单事件**后逐条判定；**同一事实不得在两个候选里重复计数**（如 Tinker Tales 与 SIGDIAL 论文集）。

**时间口径**：`2026-09-28—10-04` 周期**尚未结束**，本目录任何计数**不得作为最终周度结论**。
