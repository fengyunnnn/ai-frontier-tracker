## 0. 三个标注口径（全表统一，先读这一节）

### 0.1 来源位置（3 值）

| 取值 | 定义 | 例 |
|---|---|---|
| **原始** | 事件主体自己发布：官方公告／产品文档／发布说明／论文原文／代码与模型仓库／标准与法规原文／采购公告／**当事人本人自述** | Apple HIG、arXiv 论文、GitHub 仓库、`cac.gov.cn`、阳光采购网公示、用户本人在投诉平台的陈述 |
| **二手** | 有编辑责任的权威或行业媒体对原始的复述，可核但须回溯 | 新华每日电讯、C114、流媒体网、TomsGuide |
| **线索** | 聚合站／门户／公众号／社交转载／**单条 UGC**，仅负责发现 | 今日头条转载、公众号、单条小红书帖 |

> **易混点**：当事人自述（投诉、差评、帖子）在「位置」上是原始，但在「证据强度」上只有线索级 —— 两个维度互不决定，与规范 §5.4 的分组／等级区分同构。

### 0.2 证据成熟度（5 值，取自规范 §3.2）

| 取值 | 定义 | 典型来源 |
|---|---|---|
| **概念** | 只有主张、设计意图、演示或设想，无可运行产物 | 设计指南、企业白皮书、发布会 |
| **实验** | 有论文／基准／可复现实验，但未工程化；**同行评审与预印本须区分** | 顶会论文、arXiv、实验室评测 |
| **开发者可用** | 有 API／SDK／权重／文档，开发者可接入，但非终端用户产品 | GitHub、Hugging Face、云厂商文档 |
| **产品可用** | 终端用户可实际使用（常带地区／机型／语种限制） | 官方帮助中心、发布说明、采购公示 |
| **规模验证** | 有独立第三方或大规模使用数据佐证 | 洛图科技、IDC、运营商公示交付量 |

### 0.3 三条硬规则（写进扫描动作）

1. **成熟度上限 ≠ 实际证据**。来源能提供的最高档位是上限；单条内容仍可能只到「概念」。例：GitHub 上限是「开发者可用」，但一个 3 star 的 demo 仓库实际证据可能只到「概念」。
2. **arXiv 不等于同行评审，也不等于产品可用**。arXiv 上限＝实验；顶会正式论文（ACM DL／ACL Anthology／ISCA Archive 有卷期页码）才可标「实验（同行评审）」。
3. **聚合与单条 UGC 不得单独构成重点事项依据**。规范 §5.3 原文：C 类线索源「不得单独作为关键事实依据」，重要内容必须回到官方公告／产品文档／论文／代码仓库／标准原文。

### 0.4 三个池（本轮统一的落点）

| 池 | 含义 | 出口 |
|---|---|---|
| **原始线索池** | 刚扫到、未分类、未核验 | 每周运行手册第 3 步的产出 |
| **候选池** | 已判断与 16 方向相关，待回溯一手源 | 进入汇总／核验 |
| **持续观察池** | 长期基线或机制性来源，定期看变化，不产出「新闻」 | 月度／季度复盘 |
